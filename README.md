# 豆包语音输入（Linux 版）

一个常驻后台的语音转文字小工具，形态就是一个极简语音输入法：**不占屏幕、按下按键就说、字实时进输入框**。

这个仓库原本是 Windows 版，现在已经改造成在本机（**Ubuntu 26.04 / GNOME 50 / Wayland / Python 3.14**）上跑的版本。协议层（SAUC 二进制帧、手写 WebSocket 客户端）没动，平台层整体换掉了。

## 和 Windows 版的差别

| 事情 | Windows 版 | 这里 |
| --- | --- | --- |
| 全局热键 | `WH_KEYBOARD_LL` 钩子 | 直接读 `/dev/input/event*`（evdev） |
| 往光标处打字 | `SendInput` 注入 | 内核虚拟键盘 `/dev/uinput`（粘贴 + 退格，不逐字敲） |
| 剪贴板 | Win32 剪贴板 API | `wl-copy` / `wl-paste`（wl-clipboard） |
| 界面 | tkinter（本机没装，也装不了） | GTK3 / PyGObject（本机自带） |
| 托盘 | `Shell_NotifyIcon` | StatusNotifierItem（GNOME 顶栏） |
| 麦克风 | winmm（`waveIn*`） | PipeWire（`pw-record`，退回 `arecord`） |
| 录音浮标 | 同进程的透明窗口 | 单独的 X11 子进程（原因见「实现说明」） |

两件事在 Linux 上做不到，先说清楚：

- **独占按键做不到**：内核这层要么"只读旁听"，要么整台键盘抓走（`EVIOCGRAB`），
  后者会让你的键盘彻底失灵。所以录音键永远和其他软件共用（右 Ctrl 本来也没用途，不影响）。
- **认不出"当前焦点是哪个窗口"**：Wayland 不提供这个接口，所以 Windows 版那套
  "目标窗口失焦就停手"的保护没有替代品。录音时别切窗口（切了字就进到新窗口里）。
- **文字一律靠剪贴板粘贴，不逐字敲键盘**：uinput 注入的按键会先经过输入法，而本机的输入法是
  libpinyin（中文拼音），注入字母会被吃进拼音候选里——实测注入 `hello world` 得到的是 `和来o`。
  所以中英文都走"写入剪贴板 + Ctrl+V"，这也省掉了任何中文输入支持。代价是剪贴板会被临时占用
  （默认说完自动还原，见设置里的「说完还原原来的剪贴板」）。

## 快速开始

1. **一次性放开设备权限**（要 sudo，装完就一劳永逸）：

   ```bash
   sudo bash setup_linux.sh
   ```

   它做三件事：写一条 udev 规则（用 `uaccess` 标签只给当前登录用户发 ACL，不用改用户组、不用重新登录）、
   让规则生效、缺 `wl-clipboard` 就顺手装上。装完自检一遍：

   ```bash
   python3 voice_input.py --self-test    # 期望全部 ✓
   python3 voice_input.py --type-test    # 把两段样例文字打进当前光标处，验证注入链路
   ```

2. **装进桌面**（不需要 root）：

   ```bash
   bash install_launcher.sh --autostart   # 装桌面项 + 登录自启；不加 --autostart 就只装桌面项
   ```

   之后在应用列表里搜「豆包语音输入」就能启动。也可以直接跑：

   ```bash
   ./启动语音输入.sh          # 或者 python3 voice_input.py
   ```

3. **填 API Key**：第一次启动会自动弹出设置面板。Key 从火山引擎控制台「API Key 管理」拿，
   `resource_id` 要和账号已开通的版本一致（本机账号是 **1.0 小时版 `volc.bigasr.sauc.duration`**）。

4. 光标点到任意能打字的地方（浏览器、编辑器、聊天窗口都行）→ **按住右 Ctrl** 说话 → 松开 → 字就在输入框里了。

没有 `config.json` 也能启动（用内置默认值），只是没 Key 无法识别；也可以用环境变量 `DOUBAO_API_KEY` 提供 Key。
配置模板在 `config.example.json`，程序会自己写入 `config.json`（含 Key，已 gitignore）。

## 怎么操作

| 按键 | 行为 |
| --- | --- |
| **按住右 Ctrl** | 一直录，**松开就结束**并把文字打进光标处 |
| **Ctrl+Alt+D** | 按一下开始录，再按一下结束（适合长时间口述） |

两个键同时生效，不用切换模式，都能在设置里改成任意按键（Fn 见下）。

状态看两处：

- **顶栏托盘图标**：灰=待机，红=录音中，橙=识别中，深红=出错。左键单击出菜单（显示主界面 / 设置 / 退出），
  双击＝显示主界面，中键＝设置。
- **桌面底部浮标**：录音时出现，圆环跟着音量转，识别中脉动，出错时带红字提示。
  浮标不抢焦点，也不挡鼠标（整块区域点击穿透）。

> GNOME 顶栏要能看到图标，靠的是自带的 `ubuntu-appindicators` 扩展（本机默认开着）。如果顶栏没有图标，
> 程序会把主界面弹出来兜底，仍然能用。

## 关于 Fn 键（本机实测结论：用不了）

**这台机器上的键盘不把 Fn 交给系统**，和 Windows 下一样：Fn 是在键盘固件层处理的，按键事件根本没进内核。
判定办法：

```bash
python3 voice_input.py --watch-keys                        # 实时列出收到的每个按键
python3 voice_input.py --detect-key --as hold --restart     # 按一下按键就设为录音键
```

- 按 Fn 时监视器里冒出 `未知键(code=464)` 之类的行 → 能用，用上面第二条命令设好即可。
- 什么反应都没有 → 键盘把 Fn 做在硬件层了。**这不是软件能绕过的**，那些"全局改键"工具同样收不到。
  想让 Fn 能用，只有让键盘自己先发出一个正常按键（厂商驱动软件 / QMK、VIA 固件里改键）。

懒得折腾就直接用右 Ctrl，本机现在的配置就是它。

## 设置项

设置面板分 5 个标签页。**没改过的可选参数不会发给服务端**，请求体保持最小。

**接口**：API Key、资源 ID、识别语种、麦克风（列出 PipeWire 的采集节点）。

**按键**：长按键 / 切换键（点「按下按键…」按一下就设好）、不独占按键（Linux 上无效，灰掉并说明原因）。

**录音**：边说边出字、非实时时结果的去向（粘贴 / 逐字键入 / 仅复制到剪贴板）、静音自动停止、
灵敏度阈值（带「检测环境噪声」按钮）、最长录音、显示浮标、主界面置顶，以及三项 Linux 特有的：

> 「逐字键入」这条在**开着中文输入法时会出错**（字母被输入法吃成拼音候选），日常建议用默认的「粘贴到光标处」。

| 设置 | 说明 |
| --- | --- |
| 说完还原原来的剪贴板 | 中文要靠剪贴板粘贴，边说边出字会反复占用剪贴板；开着就在说完后把原来的内容放回去。关掉则剪贴板里最后留的是识别结果 |
| 上屏间隔 | 毫秒，默认 350。上屏是"写剪贴板 + 按 Ctrl+V"，而**每次写剪贴板都要抢一次键盘焦点**（GNOME 的限制，见下），所以把中间结果攒一下再一起打：调小更跟手、调大更省（也少打断焦点） |
| 粘贴快捷键 | **自动识别**（默认）/ 总是 Ctrl+V / 总是 Ctrl+Shift+V。终端的粘贴键是 Ctrl+Shift+V，别的程序是 Ctrl+V；自动识别会通过无障碍接口（AT-SPI）问「现在焦点窗口是谁」，命中终端名单就用 Ctrl+Shift+V，查不出来时回退到这里的固定选择 |
| 同时发系统通知 | 识别完成/出错时再发一条 GNOME 通知。浮标不显示或看不见时的兜底提示 |

**识别**（对应接口的 `request` 字段）：智能标点 `enable_punc`、数字规范化 `enable_itn`、语义顺滑 `enable_ddc`、
自动识别语种 `enable_auto_lang`、中英文及方言 `enable_lid`、繁体输出 `output_zh_variant`、结果返回方式 `result_type`、
流式二遍识别 `enable_nonstream`，以及分句信息 / 说话人分离 / 情绪 / 性别 / 年龄这些附加信息开关。

**高级**：判停静音阈值 `end_window_size`、分句静音阈值 `vad_segment_duration`、起始强制有声 `force_to_speech_time`、
热词、对话上下文、敏感词过滤、地名优先、音乐优先。

> 首次启动会自动测一次环境噪声并把灵敏度阈值调到合适值（本机环境噪声偏大，默认的 200 会让"静音自动停止"
> 永远不触发），测完会提示一句；之后可以在设置里手动改或重新检测。

## 命令行

```bash
python3 voice_input.py                  # 启动（默认就是后台常驻模式）
python3 voice_input.py --self-test      # 自检：权限、键盘、麦克风、按键注入、剪贴板、常驻实例
python3 voice_input.py --type-test      # 把两段样例文字打进当前光标位置，验证注入链路
python3 voice_input.py --list-devices   # 列出麦克风
python3 voice_input.py --show-config    # 打印当前配置（API Key 已打码）
python3 voice_input.py --file a.wav     # 识别本地 wav，用来快速验证 Key / 资源 ID
python3 voice_input.py --watch-keys     # 实时显示按键
python3 voice_input.py --detect-key --as hold --restart

python3 voice_input.py --settings       # 让正在运行的实例打开设置
python3 voice_input.py --show / --toggle / --quit / --status
```

`--api-key / --resource-id / --language / --endpoint` 临时覆盖，不写回文件。

程序有**单实例保护**：重复启动不会开出两个后台进程，而是让旧的自己退出、新的接管
（所以"再启动一次"就等于"重启"）。`--settings` 这些命令也是通过同一个 UNIX 套接字
（`$XDG_RUNTIME_DIR/doubao-voice.sock`）找到正在跑的实例。

`--file` 只接受未压缩的 16 位 PCM wav：

```bash
ffmpeg -i 录音.m4a -ac 1 -ar 16000 -c:a pcm_s16le out.wav
```

## 常见问题

**`--self-test` 说 `/dev/uinput 不可写` / `/dev/input/event* 不可读`**
没跑过 `sudo bash setup_linux.sh`，或者跑完没重新登录。跑完脚本再自检一次。

**提示「API Key 无效或已被停用」**：Key 复制错了或被停用，去控制台重新生成。

**提示「当前账号没有开通这个资源（requested resource not granted）」**：Key 是好的，
但「资源 ID」对应的模型没开通，2.0 和 1.0 的 ID 完全不通用。

**按了键没反应**：先看顶栏图标颜色有没有变红。没变说明按键没被捕获到——用 `--watch-keys` 确认这个键
有没有进系统；变了但没字，看浮标或通知里的错误提示。

**识别结果没打进输入框**：先跑 `python3 voice_input.py --self-test`，看「焦点窗口」那一节认得对不对
（在终端里跑它，它就该认出「终端：ptyxis」并用 Ctrl+Shift+V）。如果认错了，把设置里的「粘贴快捷键」
从「自动识别」改成固定的那个；如果是需要管理员权限的窗口，Wayland 下没有 Windows 那种限制，一般不受影响；
再不行用主界面「复制」手动粘贴。

**热键绑在 Alt / Shift 上时粘贴偶尔没反应**：我们合成粘贴前会先把你还按着的修饰键抬起来
（见「实现说明」），正常不会发生；真遇到就把热键换成右 Ctrl 或 F9 这类不吃修饰的键。

**打字打错地方了**：录的时候切了窗口。Linux 下没法知道焦点窗口是谁，所以切走之后字会打进新窗口——
这是平台限制，不是 bug。

**中文进去得慢 / 剪贴板被改了**：所有文本都是"写入剪贴板 + 按 Ctrl+V"送进去的（原因见「实现说明」），
所以剪贴板一定会被临时占用。开着「说完还原原来的剪贴板」的话，说完就还原。觉得上屏节奏跟不上手，
在设置里把「上屏间隔」调小（比如 150ms）；想少打扰剪贴板和焦点就调大（比如 600ms）。

**开了输入法（拼音）时注入的英文字母变成中文**：这是输入法接管键盘的正常行为，本程序不逐字敲键盘
就是为了绕开它。如果手动把「结果的去向」改成「逐字键入」，就会踩到这个；改回「粘贴到光标处」即可。

**偶尔"说的话没被录上"**：先看识别完成后主界面的提示——如果写着「网络抖动，已自动重连并补齐音频」
说明是网络那次抖动，音频已经补齐、文字是完整的；如果写着「已保留识别到的部分」，说明那次断线太久
（重连 3 次都没成），只保住了已经识别出来的字。要是写着「采集端丢了约 N 秒音频」，那是系统忙导致
采集缓冲溢出，跟网络无关。

**静音自动停止不灵**：先点设置里的「检测环境噪声」重设阈值。阈值**太高**会把说话也当静音（录到一半
就停），**太低**就永远不停（一直录到你再按一次键）。本机麦克风增益拉得很高（环境噪声 RMS 就有九千多），
所以自动校准出来的阈值也比较大；长按说话不受这个影响，松手才停。

**看不到浮标**：浮标是 X11（XWayland）子进程画的，理论上一直在最上层。看不到就靠顶栏图标判断状态，
或者在设置里打开「同时发系统通知」。

**按住右 Ctrl 时别的软件也响应了**：右 Ctrl 单独按住没有用途，正常无感。要是把录音键改成 F2 这类有用途的键，
那个软件会同时收到——Linux 下没法只吞这一个键（见开头「和 Windows 版的差别」）。

## 实现说明

- **热键**：直接读 `/dev/input/event*`，只读旁听、不独占。这样能拿到**按键抬起**（长按说话的必需品），
  也能拿到任意键的内核键码。设备列表从 `/sys/class/input/*/capabilities/key` 里按"有没有 A/Z 键"过滤，
  免得把电源键、视频总线这些也当键盘；键盘热插拔每 2 秒重扫一次。配置里的按键规格是 `修饰键位:内核键码`
  （例如右 Ctrl 是 `0:97`），旧 Windows 配置里的三段式会被自动换算过来。
- **注入**：`/dev/uinput` 建一个名为 `Doubao Voice Virtual Keyboard` 的虚拟键盘。三个实测踩过的坑：
  ① 虚拟键盘必须用 `UI_SET_KEYBIT` 把要发的键码**声明进能力位图**，否则内核直接丢弃（第一版漏了退格 14，
  表现是"退格完全没反应"），现在干脆把 1~255 全声明上；② `UI_SET_EVBIT/KEYBIT` 收的是**值本身**而不是
  指针（传 buffer 会被当成巨大位号 → EINVAL）；③ `wl-copy` 的父进程在选区交接完成前就返回，紧接着
  按 Ctrl+V 会粘到空内容，所以写完剪贴板要回读一次确认。发送前先按下、发 SYN、再抬起；这个设备名会被
  热键那边跳过，避免自己触发自己。
- **浮标为什么要单开进程，还非得是 X11**：实测本机 Wayland 下**任何新窗口都会抢焦点**（GTK3/GTK4 都一样），
  一抢焦点正在打字的窗口就收不到字了；而 X11 的 override-redirect 窗口不受窗口管理器管辖，抢不到焦点
  （`Gdk.Window.set_override_redirect`，实测确认过）。主进程保持 Wayland 客户端是有原因的：本机
  XWayland 和 Wayland 之间的剪贴板**不互通**（两个方向都实测过），跑在 X11 上的话剪贴板就是废的。
- **剪贴板为什么用 wl-clipboard**：本机实测 GTK3/GTK4 的剪贴板 API 对没有窗口的后台程序不生效——
  `wl-paste` 读不到 GTK 设进去的内容，反过来 `wl-copy` 设的 GTK 也读不到。
- **终端 vs 别的窗口怎么区分粘贴键**：终端的粘贴是 `Ctrl+Shift+V`，别的程序是 `Ctrl+V`，发错了字就进不去。
  这里照 doubao-murmur 的思路做成**自动识别**：查当前焦点窗口，命中终端名单（ptyxis、gnome-terminal、
  kitty、konsole、alacritty、wezterm、xterm… 约 50 个，含反写域名形式）就发 `Ctrl+Shift+V`。
  查"焦点窗口是谁"在 GNOME Wayland 下是难点，本机实测过三条路：
  **① AT-SPI（无障碍总线）可用**——屏幕阅读器那套接口工作在工具包层，Wayland/X11 通吃，能读到带
  ACTIVE/FOCUSED 状态的窗口及其应用名（实测认出了 ptyxis）；缺点是没开无障碍的程序查不到、一次遍历
  约 100ms，所以按会话只查一次。**② X11 的 `_NET_ACTIVE_WINDOW` 只在 X11 会话或焦点是 XWayland 程序时有效**
  （实测 GNOME Wayland 下它不跟着 Wayland 窗口走，拿到的窗口连 WM_CLASS 都没有）。**③ GNOME 的
  `org.gnome.Shell.Introspect.GetWindows` 被系统拒绝**（`GetWindows is not allowed`），`Shell.Eval` 也已禁用。
  所以：AT-SPI 查得到就自动判断，查不到就用设置里的固定选择，绝不瞎猜。
- **发粘贴前先抬起残留修饰键**：热键如果绑在 Alt / Shift / Super 上，用户说话时那个键还按着，我们合成的
  `Ctrl+V` 就会被目标程序看成 `Ctrl+Alt+V` 或 `Ctrl+Shift+V`——要么被当快捷键吃掉、要么不粘贴，反正字丢了。
  所以注入前先用 `EVIOCGKEY` 读一下内核里"现在哪些修饰键是按下的"（和 Windows 的 `GetAsyncKeyState` 等价），
  把还按着的那几个补一个抬起事件再发粘贴（doubao-murmur 的 `release_stuck_modifiers` 就是这么做的）。
- **上屏为什么是攒批的**：mutter 的 `meta-wayland-data-device.c` 里，`set_selection` 会拿
  `wl_resource_get_client(resource) != data_device->focus_client` 直接拒绝——也就是说**写剪贴板的
  那一刻必须拥有键盘焦点**（serial 反而不校验，源码里那句 FIXME 就是这个意思）。所以每一次写剪贴板
  都是一次"抢焦点 → 写 → 还焦点"的往返，实测单次约 100 毫秒（其中等焦点约 50ms、回读确认约 50ms），
  还会打断一次焦点。中间结果一秒能来四五次，每次都写既慢又扰民，于是默认攒 350ms（或满 6 个字、
  或说到句号问号）再一起上屏：一次 5 秒口述的写入次数从 33 次降到 14 次，识别线程被堵的时间
  从 3.6 秒降到 1.4 秒。想更跟手/更省可以在设置里调「上屏间隔」。
- **网络抖动不再吞掉整段话**：识别是边录边发（每 200ms 一片），原来任何一次发送失败都会让整段识别
  直接报错丢弃。现在：采集到的音频全程攒在内存里（上限 30 秒），发送进度单独记录；一旦发送超时/断连，
  就自动重连并把**已经发出去的那部分音频重放**给新连接（新连接从头转写），未发的尾巴继续正常发，
  末包标记也不会丢。重连最多 3 次（退避 0.5/1.2/2.5 秒）。实测用假服务端制造断线：第二条连接收到了
  完整 64000 字节音频、文字一字不少；如果重连始终失败，**已经识别出来的文字会照常返回**并在提示里
  说明（原来这种情况是整段丢弃）。
- **"卡住几秒才出字"的元凶：把网络重传误判成断线**。原来 socket 的收发超时统一是 0.5 秒，
  而对端 RTT 约 200ms，一次 TCP 重传就要 0.6~1.4 秒——于是正常的重传被当成"连接已死"，
  触发重连（TCP+TLS+握手 ≈1.5 秒），这段时间里一个字都不出，重连后文字才一股脑冒出来。
  现在把两件事分开：**空闲检测**用 0.4 秒的 `select` 轮询（不算异常，读线程照常醒着），
  **发送/读到一半**给 5 秒容忍度（实测：一个故意不读数据的连接，发送被压满时 5.3 秒才判超时，
  旧实现 0.5 秒就误判）。另外握手超过 1.2 秒会提示「正在连接识别服务…（网络较慢）」，
  不让用户干等着猜。
- **服务端能吃突发**：实测把 2 秒音频不限速一次灌进去，服务端 1 秒内把 12 个响应全回完，
  所以不需要为了"投喂太快"做限速。（反过来也说明：出字慢不是投喂策略的问题。）
- **发送失败重启顺序**：`recv_frame` 现在区分"空闲超时"（没事，继续等）和"读到一半超时"
  （连接已不可信，必须重连）——否则下次会把半个帧体当帧头读，整个流错位。
- **录音**：`pw-record`（PipeWire）采 16kHz/16bit/单声道，没有 PipeWire 时退回 `arecord`，
  每 100ms 一块进队列。松手时多读一个周期，把收集端里还没读回来的那块收干净
  （这段音频正好是一个字的长度，丢了很明显）。
- **流启动爆音**：本机采集流刚打开的 0.3~0.9 秒里经常吐满量程的假信号（RMS 直接顶到 32768，约半数打开会碰上），
  所以开头 1.2 秒内 RMS 超过 24000 的块会被换成等长静音——既清掉噪声，也不打乱时间轴。
- **实时上屏**：流式结果的文字会增长也会修订。本地维护一份"已经打进去的内容"，每次只补新字；
  需要改动时退格到最长公共前缀再重打，单次回退超过 40 字就跳过等最终结果兜底（防止识别跳变删掉你已有内容）。

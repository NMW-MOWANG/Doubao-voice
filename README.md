# 豆包语音输入

一个常驻后台的 Windows 语音转文字小工具，形态就是一个极简语音输入法：**不占屏幕、按下按键就说、字实时进输入框**。

- **零第三方依赖**：只用 Python 标准库（`tkinter` + `ctypes`），不装 numpy / pyaudio / websockets / pystray
- **两种触发方式**：长按说话（松开即停）+ 按一下开始/再按结束
- **边说边出字**：走流式接口，识别结果实时打进光标处，中途的修正会自动退格重打
- **后台常驻**：没有主窗口，托盘图标 + 录音浮标就是全部界面
- 默认识别普通话

## 快速开始

1. 确认已安装 Python 3.8 以上（开发环境为 3.13），安装时勾选 "Add Python to PATH"。
2. 双击 `启动语音输入.bat`。
3. 光标点到任意能打字的地方（微信、浏览器输入框、编辑器都行）→ **按住右 Ctrl** 说话 → 松开 → 字就在输入框里了。

首次运行前先把配置模板复制成 `config.json`（`config.json` 含 API Key，属于个人配置，不进版本库）：

```bash
cp config.example.json config.json
```

然后把控制台「API Key 管理」里的 Key 填进 `api_key`，`resource_id` 改成账号已开通的那版（见下方「接口」表）。没有 `config.json` 也能启动，用的是内置默认值，只是没 Key 无法识别；也可以用环境变量 `DOUBAO_API_KEY` 提供 Key。改好配置后直接在设置面板里改也等价，程序会写回 `config.json`。

## 怎么操作

| 按键 | 行为 |
| --- | --- |
| **按住右 Ctrl** | 一直录，**松开就结束**并把文字打进光标处 |
| **Ctrl+Alt+D** | 按一下开始录，再按一下结束（适合长时间口述） |

两个键是同时生效的，不用切换模式。都能在设置里改成任意按键（包括 Fn，见下）。

> **这两个键不会被本程序独占**：钩子只"旁听"，按键照常传给其他软件。右 Ctrl 单独按住本来就没有任何作用，所以共用它没有任何副作用；F2 就不一样了（资源管理器里是重命名、VSCode 里是重命名符号），按住 F2 说话时它们会同时收到。长按期间的连发（自动重复）会被挡掉，不会往输入框刷一串。想彻底不让其他软件收到，在设置里取消勾选「不独占按键」。

录音时桌面底部会出现一个小麦克风浮标：红圈=在录，圆环跟着音量转；黄圈=识别中；绿圈一闪=完成；红圈带错误信息=出错了。浮标不抢焦点，你正在打字的窗口不会掉焦点。

## 托盘图标

程序是后台常驻的，**没有主窗口**，控制入口在系统托盘的麦克风图标上：

- **左键单击** → 菜单（显示主界面 / 设置 / 退出），图标颜色跟着状态变（灰=待机，红=录音中，橙=识别中）
- **双击** → 打开设置

> Windows 11 会把新程序的通知图标默认折叠到任务栏的 `^` 面板里。想让它常驻在任务栏上：**设置 → 个性化 → 任务栏 → 其他系统托盘图标**，把 Python 那一项打开。找不到图标时也可以在任务管理器里结束 pythonw.exe。

主界面（托盘菜单 → 显示主界面）里有识别历史、复制按钮、**退出**按钮，关掉它只是隐藏，不影响后台运行。

## 关于 Fn 键（本机实测结论：用不了）

**这台机器上的键盘不把 Fn 交给 Windows**，实测确认过：用监视器看，A、D、Shift、F2 都能收到，唯独 Fn 一个事件都没有，用户也确认确实按了。

判定办法：

```bash
python voice_input.py --watch-keys          # 实时列出收到的每个按键
python voice_input.py --detect-key --as hold --restart   # 按一下按键就设为录音键
```

- 按 Fn 时监视器里冒出 `未知键(vk=0xFF scan=0x63)` 之类的行 → 能用，按上面第二条命令设好即可。
- 什么反应都没有 → 键盘把 Fn 做在了硬件层，按键事件根本没进 Windows。**这不是软件能绕过的**，那些号称"全局改键"的工具同样收不到，因为系统层面压根没有这个按键。

想让 Fn 真的能用，只有让**键盘自己**先发出一个正常按键：

1. 装键盘厂商的驱动软件（多数机械键盘都有改键功能，QMK / VIA 键盘可以直接在固件里改），把 Fn 映射成别的键（比如右 Ctrl 或 F9）；
2. 再跑 `python voice_input.py --detect-key --as hold --restart` 捕获那个键。

懒得折腾的话，直接用一个本来就没被占用的键更省事——**右 Ctrl** 就是本机现在的配置。

## 设置项

设置面板分 5 个标签页，共 30 多个可调参数，基本覆盖了官方文档里能自定义的项。

**接口**

| 设置 | 说明 |
| --- | --- |
| API Key | 控制台「API Key 管理」获取，存在 `config.json` 里 |
| 资源 ID | 必须和已开通的版本一致。本机账号是 **1.0 小时版 `volc.bigasr.sauc.duration`** |
| 识别语种 | 默认普通话 `zh-CN`，可留空自动判断 |
| 麦克风 | 多设备时选一个 |

**按键**

| 设置 | 说明 |
| --- | --- |
| 长按键 / 切换键 | 点「按下按键…」按一下就设好了 |
| 不独占按键 | 默认开着：录音键照常传给其他软件。关掉则本程序独占，其他软件收不到 |

**录音**

| 设置 | 说明 |
| --- | --- |
| 边说边出字 | 开=流式接口 + 实时上屏；关=整句识别完再一次性粘贴 |
| 非实时时 | 结果去哪：粘贴到光标处 / 逐字键入 / 仅复制到剪贴板 |
| 静音自动停止 | 说完停顿一会儿自动结束（长按模式不生效，因为松手才是结束信号） |
| 灵敏度阈值 | 低于它算静音。**建议先点「检测环境噪声」**自动填一个值 |
| 最长录音 | 兜底保护，默认 300 秒，防止按键卡住 |
| 浮标 / 置顶 | 界面显示相关 |

**识别**（对应接口的 `request` 字段）

| 设置 | 对应参数 | 说明 |
| --- | --- | --- |
| 智能标点 | `enable_punc` | 加逗号句号问号 |
| 数字规范化 | `enable_itn` | 「一九七零年」→「1970 年」 |
| 语义顺滑 | `enable_ddc` | 删掉"嗯、那个"，**也会删掉"呀、啊、呢、吧"这类语气词**（说"你好呀"只会得到"你好"）。默认关闭 |
| 自动识别语种 | `enable_auto_lang` | 模型自己判断语种；**与热词/上下文不能同时用** |
| 中英文及方言识别 | `enable_lid` | 普通话、粤语、四川话等自动判断 |
| 繁体输出 | `output_zh_variant` | 大陆繁体 / 台湾正体 / 香港繁体 |
| 结果返回方式 | `result_type` | 整体返回 / 只返回新增分句 |
| 流式二遍识别 | `enable_nonstream` | 仅流式接口有效，更准但更慢 |
| 分句信息、说话人分离、情绪、性别、年龄 | `show_utterances`、`enable_speaker_info`、`enable_emotion_detection`、`enable_gender_detection`、`enable_age_detection` | 开会记录用得上，日常听写没必要开 |

**高级**

| 设置 | 对应参数 | 说明 |
| --- | --- | --- |
| 判停静音阈值 | `end_window_size` | 0=用服务端默认（800ms），调小更容易断句 |
| 分句静音阈值 | `vad_segment_duration` | 0=用服务端默认（3000ms） |
| 起始强制有声 | `force_to_speech_time` | 防开头被切掉，推荐 1000 |
| 热词 | `corpus.context` | 每行一个，提高专有名词识别率 |
| 对话上下文 | `corpus.context` | 贴上一句对话帮助理解语境 |
| 敏感词过滤 | `sensitive_words_filter` | 系统词库 / 替换为空 / 替换为 `*` |
| 地名优先、音乐优先 | `enable_poi_fc`、`enable_music_fc` | 调用领域推荐词服务 |

> 原则：**没改过的可选参数不会发给服务端**，请求体保持最小，避免干扰服务端默认行为；改了才发。

## 命令行

```bash
python voice_input.py                 # 启动（默认就是后台常驻模式）
python voice_input.py --list-devices  # 列出麦克风设备
python voice_input.py --show-config   # 打印当前配置（API Key 已打码）
python voice_input.py --file a.wav    # 识别本地 wav，用来快速验证 Key / 资源 ID
python voice_input.py --detect-key --as hold --restart   # 按一下按键就设成录音键

--api-key / --resource-id / --language / --endpoint   临时覆盖，不写回文件
```

`--detect-key` 的 `--as` 可选 `hold`（长按键）或 `toggle`（切换键），`--key-timeout` 调整等待秒数。

程序有**单实例保护**：重复启动不会开出两个后台进程，而是让旧的自己退出、新的接管。所以「重新双击 `启动语音输入.bat`」就等于「重启程序」，改完配置直接这么做即可。

`--file` 只接受未压缩的 16 位 PCM wav：

```bash
ffmpeg -i 录音.m4a -ac 1 -ar 16000 -c:a pcm_s16le out.wav
```

## 常见问题

**提示「API Key 无效或已被停用」**
Key 复制错了或者被停用，去控制台重新生成。

**提示「当前账号没有开通这个资源（服务端：requested resource not granted）」**
Key 是好的，但「资源 ID」对应的模型没开通。2.0 和 1.0 的 ID 完全不通用，换成已开通的那版即可。

**按了键没反应**
先看托盘图标颜色有没有变红。没变说明按键没被捕获到（可能被别的软件抢了，或者 Fn 这类硬件级按键）。变了但没字，看浮标上的错误提示。

**识别结果没打进输入框**
目标窗口如果是以**管理员身份**运行的，Windows 不允许普通程序给它发按键。此时可以用托盘菜单打开主界面手动复制，或者右键用管理员身份运行 `启动语音输入.bat`。

**打字打错地方了**
实时上屏只在「录音开始时记住的那个窗口」仍是前台时才打字，中途切走就会自动停手并把完整文本放进剪贴板。

**一直录不完**
长按模式松手即停；切换模式靠静音自动停止，如果阈值比你的说话音量大就会一直录，调低它或看音量条有没有动。

**按住录音键时，别的软件也响应了（比如 VSCode 弹出重命名）**
这是「不独占按键」的代价：按键照常传出去，那个软件就看到了一次 F2。两种解法：取消勾选「不独占按键」让它独占；或者把长按键换成一个别的软件不用的键（例如 `右Ctrl`、`F9`）。F2 在资源管理器、VSCode、Word 里都有用途，共用时冲突最明显。

## 实现说明

- **按键**：用 `WH_KEYBOARD_LL` 底层钩子而不是 `RegisterHotKey`——只有钩子能拿到**按键抬起**事件（长按说话的必需品）和任意键的扫描码（Fn 这类键的唯一希望）。钩子回调运行在系统输入路径上，所以里面只做查表 + 投队列，绝不阻塞。
- **按键共用**：钩子命中录音键后默认返回 `CallNextHookEx`，即"只旁听、不拦截"，其他软件照常收到；只有长按期间的自动重复会被吃掉（否则按住时会往输入框刷一串 F2）。关闭「不独占按键」后才返回 1 把事件吃掉。
- **实时上屏**：流式接口的文字会增长也会修订。本地维护一份"已打进窗口的内容"，每次只补新字；需要改动时退格到最长公共前缀再重打，单次回退超过 40 字则跳过等最终结果兜底（防止识别跳变把用户已有内容删掉）。
- **不抢焦点**：浮标窗口带 `WS_EX_NOACTIVATE`，所以录音时你的输入框一直是前台窗口，字才能打进正确的地方。
- **音频**：`winmm` 的 `waveIn*`，16kHz/16bit/单声道，每 100ms 一块；每 200ms 一片送服务端，末包用负数 `seq` 标记结束。
- 官方 demo 解压在 `_ref/sauc_python/`，可用于对比协议实现。
